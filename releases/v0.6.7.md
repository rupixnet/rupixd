## Rupix v0.6.7 — Checkpoint #3, shared from birth

**No consensus change.** Same keys, same data; only the binary changes. Update before DAA 2,600,000 (~Oct 25): the previous list expires there.

- **Checkpoint #3** (blue score 1,987,200, DAA 1,987,552, `64305497e2210ec8…`). For the first time a checkpoint is born confirmed by a node that is not ours: the seed and community node #2 (JC) reported the same pruning point at the same time, and `GetBlock` from both returned the same block. Full record in CHECKPOINTS.en.md.
- **Checkpoint #2, external confirmation closed**: JC's node, synced from scratch, imported the pruning-point list containing it and is on the same chain as the seed.
- The list now expires at DAA 3,900,000; #4 will be published before DAA 3,600,000.
- **`rupixwallet verificar`** no longer shows FALLO on a correct node: a checkpoint below your pruning point cannot be re-read over RPC; it now says AVISO and explains why (your node enforced it when syncing).
- Explorer and website (live since Oct 20): explorer home in English, Home button, node names read from the real greeting, rename without losing the number, `/api/estado`, menu and "Rupix, live" on rupix.network.

Verify your download with `SHA256SUMS-<os>.txt` or with `rupixwallet --testnet verificar`.
